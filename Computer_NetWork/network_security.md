![](images/exampleOfBlock.png)
直接使用一个 **64 比特输入到 64 比特输出的大型查找表**，需要为全部 $2^{64}$种输入分别保存一个 64 比特输出，因此表的规模达到 $2^{64} $项，几乎无法实际存储。分组密码通常采用“小表 + 多轮迭代”的方式代替这种巨大映射：将 64 比特输入拆成 8 个 8 比特块，每个块通过一个 8 比特到 8 比特的排列表 $T_i$，因此每张表只需要 $2^8=256$ 项，8 张表总共只需要 $8\times2^8$ 项。之后利用 64 比特置乱函数将各个小块的输出比特重新分散，再进行下一轮处理，使一个输入比特的影响逐渐扩散到整个 64 比特输出。如果同一组表在每一轮重复使用，那么 n 轮只会增加计算量，**不会增加表的存储量**；因此可以用规模很小的 $8\times2^8$ 个表项，通过“**小型替换表 + 置乱 + 多轮循环**”实现原本需要巨大 $2^{64}$ 映射表才能达到的复杂变换效果。

## 密码块链接（Cipher Block Chaining，CBC）
块密码面临相同的一块加密后得到的块也是一样的
（假设映射密码如图1）
比如100 100 100 三块加密出来一定都是 011 011 011

**密码块链接**
通过在开头引入一个 c0 比如 100
m1 $\oplus$ c0 = 000 通过块密码加密后记作 c1 = 110
m2 $\oplus$ c1 = 010 通过块密码加密后记作 c2 = 101
m3 $\oplus$ c2 = 001 通过块密码加密后记作 c3 = 111

一节一节分析
-Alice 发送 c0 = 100 和 c1 = K(m1 $\oplus$ c0) = 110
-Bob 解密(查表) 得到 m1 $\oplus$ c0 = 000
计算 m1 = (m1 $\oplus$ c0) $\oplus$ c0 = 000 $\oplus$ 100 = 011
-Truder 收到 c1 没法解密，只知道 有 100 110 两组数据

-Alice 发送 c2 = K(m2 $\oplus$ c1) = 101
-Bob 解密(查表) 得到 m2 $\oplus$ c1 = 010
计算 m2 = 010 $\oplus$ 110 = 011
-Truder 收到 c2 没法解密，只知道 101

-Alice 发送 c3 = K(m3 $\oplus$ c2) = 111
-Bob 解密(查表) 得到 m3 $\oplus$ c2 = 001
计算 m3 = 001 $\oplus$ 101 = 011
-Truder 收到 c2 没法解密，只知道 111

Alice 收到 *100（非内容）* 011 011 011
Truder 则收到 100 110 101 111
