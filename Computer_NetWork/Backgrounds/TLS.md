# IPsec 与 VPN 隧道模式

## 1. IPsec 是什么？

**IPsec（Internet Protocol Security）不是一种新的 IP 协议，也不是新的 IP 地址。**

它是一套用于保护 IP 数据包安全的协议。

主要提供：

* 机密性（Confidentiality）：加密数据，防止窃听
* 完整性（Integrity）：检测数据是否被修改
* 身份认证（Authentication）：确认通信双方身份
* 防重放攻击（Replay Attack）

常用于：

* VPN
* 企业总部与分支机构安全通信

---

# 2. VPN 的基本思想

普通互联网通信：

```
总部电脑
   |
   |
 公共互联网
   |
   |
分支机构服务器
```

问题：

* 数据经过公网
* 容易被监听
* 内部 IP 地址无法直接通过公网路由

VPN 希望实现：

```
总部网络
    |
    |
  安全隧道
    |
    |
分支机构网络
```

让两个远程网络看起来像处于同一个私有网络。

---

# 3. IPsec 工作位置

IPsec 工作在网络层：

```
应用层
 HTTP

传输层
 TCP / UDP

网络层
 IP
 |
 IPsec
```

因此它可以保护各种上层协议：

* HTTP
* FTP
* TCP
* UDP

---

# 4. IPsec 隧道模式（Tunnel Mode）

## 原始 IP 数据包

发送前：

```
+----------------+
|  IP首部         |
+----------------+
| TCP/UDP 数据    |
+----------------+
```

例如：

```
源IP：
192.168.1.10

目的IP：
192.168.2.20
```

表示：

```
总部电脑 → 分支服务器
```

---

# 5. IPsec 封装过程


![](../ipsec_format.png)

IPsec 不修改原始 IP 首部。

而是：

> 把整个原始 IP 数据包放入新的安全包中。

过程：

```
原始数据包

IP首部
+
TCP数据


↓

整体加密


↓

添加新的外层IP首部
```

最终：

```
+--------------------+
| 新IP首部            |
+--------------------+
| ESP首部             |
+--------------------+
| 加密后的原始IP包    |
| (原IP首部+数据)     |
+--------------------+
| ESP尾部             |
+--------------------+
| ESP MAC             |
+--------------------+
```

---

# 6. 新 IP 首部和初始 IP 首部区别

## 新 IP 首部（外层）

作用：

> 让公网找到 VPN 对端。

例如：

```
源IP：
总部VPN网关公网IP

目的IP：
分支VPN网关公网IP
```

公网看到：

```
总部VPN网关
        |
        |
分支VPN网关
```

---

## 初始 IP 首部（内层）

作用：

> 表示真正的通信双方。

例如：

```
源IP：
总部电脑

目的IP：
分支服务器
```

公网无法看到，因为已经被加密。

---

# 7. 为什么需要两个 IP 首部？

因为两个 IP 首部负责不同任务。

| IP首部   | 作用           |
| ------ | ------------ |
| 外层IP首部 | 公网路由，找到VPN网关 |
| 内层IP首部 | 内部通信，找到最终主机  |

类似：

```
大信封：

寄件人：
总部VPN

收件人：
分支VPN


里面的小信封：

寄件人：
总部电脑

收件人：
分支服务器
```

---

# 8. ESP（Encapsulating Security Payload）

ESP 是 IPsec 中负责安全保护的协议。

结构：

```
+-----------+
| ESP首部   |
+-----------+
| 加密数据  |
+-----------+
| ESP尾部   |
+-----------+
| ESP MAC   |
+-----------+
```

---

# 9. ESP 首部

ESP 首部：

```
+-------------+
| SPI         |
+-------------+
| 序号        |
+-------------+
```

---

## SPI

Security Parameter Index

作用：

> 指示使用哪一个安全策略和密钥。

例如：

```
SPI      密钥

1001     Key-A
1002     Key-B
1003     Key-C
```

收到：

```
SPI=1001
```

查表：

```
使用 Key-A 解密
```

---

## 序号

作用：

防止重放攻击。

例如：

正常：

```
1
2
3
4
```

攻击者重新发送：

```
2
```

接收方发现：

```
2 已经使用过
```

直接丢弃。

---

# 10. ESP 尾部

ESP尾部：

```
+-------------+
| 填充        |
+-------------+
| 填充长度    |
+-------------+
| 下一个首部  |
+-------------+
```

## 填充

原因：

很多加密算法要求固定块长度。

例如 AES：

```
16字节一组
```

数据：

```
30字节
```

补：

```
2字节
```

变成：

```
32字节
```

---

## 填充长度

告诉接收方：

```
删除多少填充
```

---

## 下一个首部

告诉接收方：

解密后是什么协议。

例如：

```
TCP
UDP
IP
```

---

# 11. ESP MAC

注意：

这里 MAC：

不是 MAC 地址。

而是：

> Message Authentication Code（消息认证码）

作用：

验证数据完整性。

发送：

```
数据
+
MAC
```

接收：

重新计算：

```
MAC = HMAC(数据, 密钥)
```

比较：

一致：

```
数据没有被修改
```

不一致：

```
数据被篡改
```

---

# 12. IPsec 总流程

发送：

```
原始IP包

↓

添加ESP

↓

加密

↓

计算MAC

↓

添加外层IP首部

↓

公网传输
```

接收：

```
收到IPsec包

↓

根据SPI找到密钥

↓

验证MAC

↓

解密

↓

删除ESP

↓

恢复原始IP包
```

# TLS 握手与密钥生成

# 1. TLS 的目标

TLS 提供：

* 加密（Confidentiality）
* 完整性保护（Integrity）
* 身份认证（Authentication）

例如 HTTPS：

```
浏览器
  |
 TLS
  |
服务器
```

---

# 2. TLS 为什么需要多个密钥？

通信有两个方向：

```
Client → Server

Server → Client
```

不能双方共用一个密钥。

因此需要：

## 加密密钥

两个：

```
Client Write Key

Server Write Key
```

## HMAC密钥

两个：

```
Client MAC Key

Server MAC Key
```

总共：

```
4个密钥
```

---

# 3. PMS（Pre-Master Secret）

握手阶段：

客户端生成：

```
PMS
```

前主密钥。

例如：

```
Client
 |
 |
 |  RSA加密PMS
 ↓
Server
```

服务器使用私钥解密得到 PMS。

---

# 4. Master Secret（MS）

双方拥有：

```
PMS
+
随机数
```

通过 TLS 密钥导出函数：

```
PMS
 |
 ↓
Master Secret
```

得到：

```
MS
```

---

# 5. MS 为什么要切片？

MS 是一个母密钥。

它不直接用于通信。

类似：

```
Master Secret

       ↓

------------------------
|      |       |       |
Kc     Ks     MACc    MACs
------------------------
```

生成：

| 名称               | 作用        |
| ---------------- | --------- |
| Client Write Key | 客户端发送数据加密 |
| Server Write Key | 服务器发送数据加密 |
| Client MAC Key   | 客户端数据完整性  |
| Server MAC Key   | 服务器数据完整性  |

---

# 6. CBC 模式是什么？

CBC：

Cipher Block Chaining

分组密码链接模式。

AES一次只能处理：

```
固定长度数据块
```

所以长数据需要分块：

```
M1
M2
M3
```

CBC：

第一块：

```
M1 XOR IV
      |
     AES
      |
      C1
```

第二块：

```
M2 XOR C1
      |
     AES
      |
      C2
```

第三块：

```
M3 XOR C2
      |
     AES
      |
      C3
```

---

# 7. IV（Initialization Vector）

中文：

初始化向量。

作用：

给 CBC 第一块提供随机输入。

因为第一块没有前一个密文：

```
M1 XOR ?
```

所以需要：

```
M1 XOR IV
```

---

# 8. 为什么需要 IV？

如果没有 IV：

相同：

```
明文
+
密钥
```

得到：

```
相同密文
```

攻击者可以发现规律。

加入随机 IV：

```
相同明文

+

不同IV

↓

不同密文
```

提高安全性。

---

# 9. TLS 完整密钥关系

```
          PMS

           |
           ↓

    Master Secret

           |
           ↓

--------------------------------
|          |          |         |
Kc         Ks       MACc      MACs
--------------------------------

           |

       TLS通信
```

如果使用 CBC：

还需要：

```
Client IV

Server IV
```

---

# 10. 最终 TLS 数据格式

发送数据：

```
应用数据

↓

MAC计算

↓

加密

↓

TLS Record
```

形成：

```
TCP
 |
 TLS加密记录
 |
 IP
```

公网：

看到：

```
客户端IP
服务器IP
```

看不到：

```
HTTP内容
账号密码
业务数据
```

# 总结对比

| 技术    | 保护对象      | 核心思想         |
| ----- | --------- | ------------ |
| IPsec | IP层数据包    | 保护网络通信       |
| TLS   | 应用层通信     | 保护应用数据       |
| ESP   | IPsec核心协议 | 加密+认证        |
| CBC   | 加密模式      | 分块加密         |
| IV    | CBC参数     | 防止相同明文产生相同密文 |
| HMAC  | 完整性       | 检测篡改         |
